- 上述证据暴露并修复九项生产缺陷：验证器原先错误地让发送与接收两个独立 checkpoint 方向共享序号，导致双边正常最终化被误判篡改；Ctrl+] 已被输入状态机识别为 detach 后，外层错误路径仍记录为 `LocalInterrupt`；controller 本地显示写入失败时没有在返回原始 I/O 错误前记录失败 outcome；首次 checkpoint ack 确认后清除了最后一次已签名 checkpoint，使文档承诺可忽略的精确 ack 重传错误地返回 `no checkpoint awaiting confirmation`；host 终端数据的网络写入成功但随后 flush 失败时，错误会向上传播，却没有先写入失败的 `LocalSendOutcome`；强制审计失败帧与终端 EOF 同时就绪时，未指定优先级的事件选择还可能随机返回普通 `UnexpectedEof`，掩盖真实的 fail-closed 根因；本地审计失败原先只发送统一 `CloseNotice`，已定义的结构化 `AuditError` 没有进入生产通知路径；controller 的普通输入及 EOF 残留输入同样只把 write 失败记录为失败 outcome，后续 flush 失败没有审计证据；文件路径提示结束后回放有界延迟输出时，write/flush 失败也会绕过 `LocalDisplayWriteOutcome`。当前实现保留最后发送的 checkpoint 作为重传校验依据；把终端数据和显示的 write/flush 分别作为完整可观测效果，仅在二者都成功后记录成功；让 controller/host 活动期事件泵在连接生命周期之后、终端 I/O 之前确定性处理审计帧；并按 `AuditError -> CloseNotice` 固定顺序尽力通知对端。新 checkpoint 会自然覆盖前一个，`awaiting_ack` 仍是唯一等待状态。九项修复均有先失败后通过的回归证据；审计故障竞态在 Windows controller 连续 `5/5` 及对称 host 场景通过，checkpoint/ack 的会话 ID、序号、摘要、快照和签名独立变异也分别验证失败关闭，在途运行 checkpoint 与正常最终化的交叠另由双边完整记录回归验证。Linux 完整 coverage 还暴露两项测试端的跨子流顺序假设：脚本必须在最终化前释放唯一审计读者，detach/interrupt 时也必须在 terminal data/control EOF 先到后继续驱动 audit CloseNotice；修正只让测试遵守协议的多子流无序与单读者不变量，不改变生产关闭语义。
- Linux coverage 与 Windows 真实 libp2p 周期场景进一步证伪了“收到 checkpoint 时双方瞬时快照必然相同”的旧假设：terminal、file、audit 独立子流只保证各自有序，晚到的合法运行期 checkpoint 可能落后于接收方当前控制链。实现现把运行期 checkpoint 定义为发送方签名观察与接收方签名回执；关闭时先记录共同关闭事实、封闭规范化方向、结清旧运行期交换，再交换快照精确相同的新最终 checkpoint。运行时及离线验证器的 sent/received 序号和确认状态均彻底分离，完整 fixture 同时交换两个 payload digest 不同的 `#1` checkpoint；双文件 interrupted 验证按方向交叉匹配并二次流式证明共享前缀。`AuditSession` 31 项、`AuditObserver` 16 项、离线 verifier 36 项以及 controller/host 两条真实周期 checkpoint E2E 均通过；其中签名、session ID、序号、digest、原快照 Ack 绑定和最终快照相等仍逐项失败关闭。
